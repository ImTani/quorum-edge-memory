FAQ: design

Why a separate key vector?

A conflict is “same thing, different value”, so matching must ignore the value and the wording. The key is just entity + attribute.

Why not let the LLM decide conflicts?

Two laptops must reach the same conflict on their own: same vectors, same query, same threshold, same id. The LLM only extracts.

Why does the demo show similarity 1.00?

Both mentions were matched to the known task “Sharma wedding edit”, so the key text is identical. Worded differently, it's 0.85–0.90.

Why templated answers?

Milliseconds, no hallucinated facts, and every sentence cites a claim.

FAQ: limits

What if the model misreads a date?

It never computes dates; code resolves them from the message. And a wrong claim can't overwrite anything: it shows up as a conflict with both sources.

Three devices? Clock skew?

Detection scales: each device finds the same conflict. The sync cursor uses device clocks; the fix is a hub-assigned sync stamp.

Does it scale?

Each question is one hybrid query or one filtered nearest-neighbour search, which is what Qdrant is built for. We haven't benchmarked large memories yet.

Business model?

Per team, per month; no price set yet. Customer zero is BKA, a four-person production house and developer group.

Concurrency and failure handling.

Crash mid-write?

Every write flushes (~28 ms), so a hard kill loses nothing. SQLite runs in WAL mode; the outbox survives restarts.

Two threads at once?

API and sync threads share one Edge shard behind a re-entrant lock. SQLite: one connection, serialised by a lock. One sync round at a time; a pull applies in one batched flush and the cursor is saved only after it lands.

Hub down?

Backoff to 5 s, “Hub down” in the UI. The collection is re-created if the hub came back empty.

Model slow or down?

6 s budget per message. After a connection error the model is skipped for 20 s; the regex fallback runs.

SSE drops?

15 s heartbeat; the page reloads state and reconnects.

Double click on Keep?

A lock: it settles once. Only the owner may resolve (403 otherwise).

Known limits

  • The pull cursor uses device clocks fix: a hub-assigned stamp
  • Conflicts are pairwise
  • The hub has no auth yet
